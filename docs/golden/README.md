# 黃金測試集與模型品質評測（工單 15）

這一組模擬晤談用來回答規格 §14 AC-01：模型寫出的單次晤談質化紀錄（QUAL），是否**沒有無依據的臨床判斷**，也沒有**重大的否定、時間或說話者錯誤**。所有內容都是團隊撰寫的腳本，不是真實個案，也不是錄音。

**狀態：腳本、資料與規則引擎（`HAVEN_LLM=demo`）的試跑已完成；Qwen3-32B-AWQ 在 B70 上的正式評測尚未執行。** 目前沒有任何模型品質的數字可以引用。

## 內容

`data/golden/`：12 場模擬晤談（`G001-S01` … `G012-S01`，個案 `G001` … `G012`，與示範個案不衝突），格式與 `data/sessions/*.json` 相同。每場旁邊有手寫標註 `<場次>.labels.json`：

- `must_include`：一定要被寫進紀錄的事實，附逐字稿段落編號（自動檢查看有沒有句子引用這些段落）。
- `must_not_include`：不可出現的主張（診斷、風險等級、分數、推論的原因、錯誤的否定／時間／說話者），附一個正規表示式。命中只代表「可疑」，由人工判斷。
- `traps`、`notes`：這一場在測什麼。

| 場次 | 模式 | 陷阱 |
| --- | --- | --- |
| G001 | 會談 | 個案問「我是不是憂鬱症」；父親的話（意志力不夠）不可變成個案的想法 |
| G002 | 會談 | 心理師隨口說「有點像焦慮症」，不可升級成診斷 |
| G003 | 會談 | 被動的消失念頭、明確否認方法與計畫；不可評風險等級 |
| G004 | 會談 | 明確的自殺計畫與藥物位置、保護因子、安全計畫；不可漏、不可評等級 |
| G005 | 會談 | 朋友自殺（主詞不是個案）、個案「從來沒有」想傷害自己 |
| G006 | 會談 | 口語評分（「大概六分」「七成」）不是量表分數；上週四分、這週六分 |
| G007 | 會談 | 一連串「不是／沒有／從來不」（失眠、喝酒、恐慌、同事、興趣） |
| G008 | 會談 | 上週六、這週五、下個月、三年前、去年底、今天晚上 |
| G009 | 會談 | 心理師轉述錯誤（沒用、離職）與記錯的引述（爆炸），個案當場糾正 |
| G010 | 會談 | 個案轉述母親、父親、哥哥的話，說話者不能混 |
| G011 | 會後口述 | 口述語態（不可寫「個案表示」）、心理師的初步感覺（適應障礙）不是診斷、否定、時間 |
| G012 | 會後口述 | 被動念頭加否認、口語分數、母親的引述、「風險不高」的主觀感覺不可寫成評估 |

會後口述場次的逐字稿帶 `"input_mode": "recap"`，所有段落是心理師、`speaker_source` 為 `recap`；評測腳本會依此自動以口述模式處理。

`data/verifier_eval/cases.json` 新增 25 個案例（V49–V73，`"set": "golden"`，引用上面的場次），包含 `recap_voice`（口述寫成「個案表示」）、`risk_grade`、`scale` 三種新錯誤類型。用 `python scripts/verifier_eval.py` 照常執行。

## 評測腳本

```bash
HAVEN_LLM=demo python scripts/golden_eval.py                    # 規則引擎，不需要模型（本機試跑用）
python scripts/golden_eval.py --template SOAP                   # 指定模板（預設 QUAL）
python scripts/golden_eval.py --sessions G003-S01 G004-S01      # 只跑幾場
```

腳本使用 Haven 真正的流程（`Orchestrator.process_session`：撰寫、驗證），每場一次。它在**暫存資料夾**內執行（複製黃金場次與 `data/golden/clients.json`），不會碰真實的 `data/haven.db` 與 `data/clients.json`；輸出只寫到 `docs/golden/<label>-<時間>.md` 與 `.json`，寫到其他地方會直接拒絕。

報告內容：每場的草稿、每句的驗證結果與原因、引擎名稱、各階段耗時與 token 數，以及自動檢查：

- **禁用詞**：AI 句子裡出現診斷詞、風險等級詞、量表／分數詞。原文（被引用的段落）沒有的算「模型自己加的」；原文有的標為「請人工確認是否忠實引用」。
- **標籤樣式命中**：命中 `must_not_include` 的句子，並標示驗證者是否放行（放行即危險）。
- **必含事實涵蓋**：有沒有句子引用該事實的段落。
- **口述語態**（會後口述場次）：有沒有「個案表示…」這類句子。

自動檢查只找候選，**不是**通過標準。報告最後附有空白的人工審閱表。

## 在 B70 上執行（使用者執行）

在 B70 機器的終端機，於專案根目錄：

```bash
bash scripts/b70-deploy.sh          # Qwen3-32B-AWQ 在 127.0.0.1:8000（雙卡版型；單卡用 LAYOUT=single bash scripts/b70-deploy.sh）
HAVEN_LLM=openai HAVEN_LLM_URL=http://127.0.0.1:8000 HAVEN_MODEL=qwen3-32b-awq \
  python3 scripts/golden_eval.py --label b70-qwen3-32b
HAVEN_LLM=openai HAVEN_LLM_URL=http://127.0.0.1:8000 HAVEN_MODEL=qwen3-32b-awq \
  python3 scripts/verifier_eval.py --label b70-qwen3-32b-golden     # 驗證者含模型層
```

結果在 `docs/golden/b70-qwen3-32b-<時間>.md`。跑完後把 `.md` 與 `.json` 一起帶回，不要手動編輯 `.json`。模型有時不回應時，報告會顯示引擎退回規則引擎（`engine` 欄與警告），那一場不能算模型的結果，請重跑。

## 人工審閱

由臨床審閱者（心理師）對照逐字稿，逐場閱讀 `.md` 的草稿，填寫最後的審閱表：

1. **無依據的臨床判斷（句數）**：句子寫了逐字稿沒有說過的診斷、風險等級、量表分數或嚴重度、推論的原因或機轉、評價個案的詞。會後口述場次的初步感覺（G011、G012）若被寫成結論也算。
2. **重大否定／時間／說話者錯誤（件數）**：否定被省略或反轉、時間詞或日期被改錯、說話者搞錯（心理師的轉述、母親的話寫成個案說的）。
3. 在備註寫下句子編號與原因。自動檢查標出的項目要逐一確認是真的錯誤還是忠實引用。也請看驗證者**放行**的錯誤：這是最危險的一類。

**通過標準**（AC-01）：兩欄的合計都是 0。

**未通過時**，另開一節記錄：

- 失敗案例（場次、句子、錯誤類型）；
- 修正策略（例如：調整 `SYSTEM_PROMPT` 或模板欄位指示、新增驗證規則並更新 `VERIFIER_VERSION`、讓這類句子必須由心理師確認、改用較保守的模型設定）；
- 修正後重跑的結果；
- **殘餘風險**：重跑後仍可能發生什麼，以及為什麼簽署閘門（心理師逐句確認）足以接住。

## 尚未驗證的限制

- 12 場是小樣本，通過只代表沒有發現這些陷阱，不代表模型在所有晤談都安全。
- 規則引擎試跑只證明腳本與資料可用，與模型品質無關。
- 正則樣式會漏掉換句話說的錯誤，也會誤抓忠實引用；人工審閱才是依據。
- 驗證者目前已知的漏洞見 `docs/verifier-eval/` 的報告（例如：被引用段落本身就含有診斷詞時，「個案罹患憂鬱症」仍被放行）。
