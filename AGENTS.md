# AGENTS.md

This file guides coding agents (Claude Code, Codex) working in this repository. It plays the role of CLAUDE.md and is shared across tools.

Haven 心港 is an on-premises AI documentation assistant for psychotherapists in Taiwan. It takes a session recording (or a therapist's post-session dictation), transcribes it (Whisper, optionally refined by Qwen3-ASR), guesses speakers (local LLM), drafts a note from a template (QUAL, SOAP or DAP) in which every sentence cites transcript segments (local Qwen), verifies each sentence against the transcript, and the therapist signs it. The original audio is kept for a limited time so the therapist can listen back (it is no longer deleted right after transcription). The clinical aids (risk cues, checklist, outcomes, Case Memory) are off by default (`HAVEN_CLINICAL_AIDS`). UI strings, prompts and lexicons are Traditional Chinese (Taiwan). All data in the repo is simulated. Spec: `docs/specs/haven-copilot-mvp.md`. Law references in the docs (心理師法第 25 條, 個資法第 6 條) are marked 待核對 and must stay marked until checked against 全國法規資料庫.

## Commands

Python 3.10+. The core uses the standard library only. Optional extras: `pip install -r requirements-asr.txt` (faster-whisper and opencc), and `pip install cryptography` (for `HAVEN_ENCRYPT=1`).

```bash
HAVEN_LLM=demo python -m haven                      # rule-based engine, no model; http://127.0.0.1:8765
python scripts/reset_demo.py                        # clean, unsigned demo DB (moves the old haven.db aside)
python -m unittest discover -s tests -v             # full suite; tests force HAVEN_LLM=demo
python -m unittest discover -s tests -p test_signing.py        # one file (tests import `helpers`, so run via discover -s tests)
python -m unittest discover -s tests -k test_sign_rules        # one test by name pattern
python scripts/verifier_eval.py                     # verifier regression on data/verifier_eval/cases.json
python scripts/benchmark.py --rooms 4               # per-agent timings, writes docs/benchmarks/
```

On PowerShell set env vars with `$env:HAVEN_LLM = 'demo'`. A single test module run as `python -m unittest tests.test_ui` fails with `No module named 'helpers'`; use `discover -s tests`.

Real models: `HAVEN_LLM=openai HAVEN_LLM_URL=http://127.0.0.1:8000 HAVEN_MODEL=qwen3-32b-awq HAVEN_ASR=openai` (vLLM on the B70, started with `scripts/b70-vllm.sh`; start Whisper first) or `HAVEN_LLM=ollama HAVEN_MODEL=qwen2.5:7b`. All configuration lives in `haven/config.py` (env vars `HAVEN_*`).

### Known test behaviour on Windows
- 5 tests assert POSIX file modes (0600/0700) and fail on NTFS: `test_password_is_stored_as_a_hash`, `test_https_with_the_made_certificate`, `test_database_and_transcripts_are_private`, `test_start_up_tightens_existing_files`, `test_temp_file_is_in_the_data_dir_and_removed_after_success`. This is a platform difference, not a regression.
- The `reset_demo.py` backup-name collision is fixed (ticket 16: microsecond names plus a counter), so `test_ui.DemoWalkthroughTest.test_5_reset_again_*` is no longer intermittent.
- Under PowerShell set `$env:PYTHONUTF8 = '1'` before running the suite (or use Git Bash); `test_accounts.test_add_user_assigns_clients` runs `scripts/add_user.py` as a child process and decodes its Chinese output with the console code page, so it can fail without it.
- 15 tests skip without `cryptography`/`opencc`; the `.gitignore` test skips outside a git checkout.

## Architecture

The request path is `web/app.js` → `haven/server.py` (one `ThreadingHTTPServer`, hand-rolled routing in `Handler._get` / `Handler._post`) → `haven/orchestrator.py` → `haven/agents/*` → `haven/store.py` (SQLite at `data/haven.db`) and transcript JSON files in `data/sessions/`.

- **Session lifecycle.** Upload (`POST /api/upload`) or browser recording (`/api/recordings` → `chunk` → `finish`) writes audio to a temp file in `data/tmp/` and answers **202 with a job id**. A worker thread (`haven/jobs.py`, `HAVEN_JOB_WORKERS`) runs `server._transcribe_job`: `audio.store_file` moves the file to `data/audio/`, `transcript.transcribe_audio` transcribes (with `HAVEN_ASR_REFINE=1`, `asr_refine.refine` replaces Whisper's words with Qwen3-ASR's, keeping Whisper's ids and times), `SpeakerAgent` labels speakers (skipped for `input_mode=recap`, where `recap.label` marks every line `speaker_source="recap"`), the transcript is saved, the session is appended to `data/clients.json`, and the note is drafted (`Orchestrator.process_session`: writer → verifier, plus risk → outcome only when `config.CLINICAL_AIDS`; the result goes to the `results` table). The page polls `GET /api/jobs/<id>`; jobs are queued → running → succeeded/failed, a restart marks running jobs `interrupted`, and `POST /api/jobs/<id>/retry` requeues a failed or interrupted one (one active job per session and kind). `POST .../process` (regenerate) is also a job (`haven/regenerate.py`). `Orchestrator.refresh` re-runs checks on an existing draft (after a speaker change, a restore, or a verifier-version change).
- **Audio lifecycle** (`haven/audio.py`, `audio_assets` table): processing → available → deleted; failed ASR keeps the file for a retry; a delete whose unlink fails becomes `cleanup_failed` and the sweep retries it (1, 5, 30 minutes, then every sweep). Deleted on signing (`HAVEN_AUDIO_DELETE_ON_CONFIRM`, default 1), at `HAVEN_AUDIO_TTL_HOURS` (default 72, a test setting, not legally checked), or by `POST .../audio/delete`. The sweeper runs at start and every 10 minutes. Audio is **not** covered by `HAVEN_ENCRYPT`. Playback (`haven/playback.py`): `POST .../audio/ticket` gives a short-lived ticket, `GET /media/audio/<ticket>` serves it with Range and no `X-Haven` header (the ticket, the cookie and the Host check are the credential); every failure is a 404. Browser-recorded `audio/webm` has `playback_supported=false` (`docs/playback-webm-seek.md`). Never reintroduce "Haven keeps no recording" wording in docs or UI.
- **Drafts vs signed notes.** The working draft lives in `results.payload` (JSON, which also holds `ai_note`, `revision`, `edited_by`). `POST .../verify` saves the edited draft; `_check_revision` rejects stale `base_revision` (409, `conflict=True`). Signing (`server._sign` + `haven/signing.py`) re-checks everything server-side: it trusts only sentence text, `evidence`, `confirmed_by_therapist` and `keep_reason` from the browser, and ignores client-sent `status`/`support`. A signed note goes to `signed_notes` (insert-only; a second insert raises `AlreadySignedError` → 409) together with its audit rows in one transaction. Corrections after signing are addenda only.
- **Verifier** (`agents/verifier.py`): hard rules (numbers, time words, pronouns, risk words and negation) → bigram/clause overlap → one batched LLM check. Verdicts are cached in the `verdicts` table keyed by transcript SHA-256 and `VERIFIER_VERSION`; bump `VERIFIER_VERSION` when rules change so stale drafts are refreshed on open.
- **Templates** (`haven/templates.py`, Template Registry): each template is a definition (id, version, name, fields with key/label/`ai_mode`/instructions/hint, plus `measures_field` and `risk_field`). SOAP, DAP and QUAL (單次晤談質化紀錄) live there; a new template is one `register(...)` call. A field's `ai_mode` is `generate` or `human_only`: QUAL's 心理師評估與概念化 and 後續計畫 are `human_only`, never sent to the model, and start as the placeholder 「待心理師填寫」 (`haven/human_fields.py`), which signing refuses until the therapist rewrites or deletes it. The default for a draft with no `?template=` is `templates.default_id()` = `config.DEFAULT_TEMPLATE` (`HAVEN_DEFAULT_TEMPLATE`, **QUAL** unless set; SOAP and DAP have A and P model-drafted). `tests/helpers.py` sets it to SOAP for the existing suite; `tests/test_default_template.py` checks the product default. Writer, signing, server (`?template=`, `GET /api/templates`, `template` in the session view) and app.js section titles read from it; an unknown id raises `UnknownTemplate` → 400. Results store `template_id`/`template_version`.
- **Writer** (`agents/writer.py`): builds the prompt from the template's `generate` fields (human_only fields are never sent); `SYSTEM_PROMPT` holds the global rules. SOAP/DAP end with an `R` (風險與安全) section (`risk_field`), and uncited high-level risk lines are force-appended there. Long transcripts are written in parts of 60 segments in parallel (`HAVEN_WRITE_PARALLEL`). With no LLM, `_rule_based` quotes the transcript.
- **Risk** (`agents/risk.py`) is lexicon/regex only, with no model. **Outcome** (`agents/outcome.py`) computes reliable change from questionnaire totals stored in `clients.json` `scores`. Score sentences are generated server-side and cannot be edited (the signing gate compares the exact text). **Risk, outcome, score lines, the risk gate on signing, forced risk quotes and Case Memory (`POST /api/clients/<id>/ask`) run only when `config.CLINICAL_AIDS` is true** (`HAVEN_CLINICAL_AIDS=1`, read at call time); by default they return `None` or do not exist. The AI does no diagnosis, risk assessment or treatment advice.
- **Speakers**: there is no acoustic diarization. `SpeakerAgent` asks the LLM to label each segment therapist/client (`speaker_source="model"`). `POST .../speakers` sets `speaker_source="confirmed"`, and prepared scripts carry `"script"`. Several rules (risk level, checklist, verifier support) branch on `speaker_source`.
- **LLM/ASR transport** (`haven/llm.py`): every outbound request goes through `assert_local` / `_checked_socket` (loopback or RFC1918 only, no proxy, no redirects). Qwen3 is called with `chat_template_kwargs.enable_thinking=False`, and `_parse_json` strips `<think>` blocks. Do not add new HTTP clients that bypass this opener.
- **Accounts** (`haven/accounts.py`): if `data/users.json` has any user, sign-in is required. `may_open` compares `client.therapist_user` with the username, and an inaccessible client/session answers 404. Admin record access is a time-limited grant with a reason (`_open_records`). Admin endpoints are loopback-only unless `HAVEN_ADMIN_FROM_NETWORK=1`. A non-loopback `HAVEN_HOST` refuses to start without accounts, TLS and `HAVEN_HOSTNAMES` (`lan_problems`).
- **Review and confirm** (`haven/transcript_edit.py`, `regenerate.py`, `recap.py`, `export.py`): `POST .../transcript` corrects a line's text or speaker (id/start/end never change, `asr_text` keeps the ASR words) and raises `transcript_revision`; draft sentences citing it get `source_changed`; `review_status` is derived, and `POST .../reviewed` records review against the current revision. Signing refuses (409, `needs_review`) until then. Saving a draft stamps each sentence's `origin` (ai / ai_edited / human) on the server; regenerating a draft with human edits is refused unless `discard_edits`, and the old draft goes to `superseded_drafts` (max 3). `GET .../export?format=md|txt` builds a file from the signed record (no transcript) and writes an `exports` row; `POST .../exports/<id>/archived` is the therapist's mark. The page calls the signing step 「確認紀錄」.
- **Storage helpers**: write files with `files.write_private` / `read_private` (they handle 0600 and optional AES-GCM via `crypto.seal`/`open_`). `store.audit` appends to a hash-chained `audit_log`; never write audit rows with raw SQL. Audit details hold ids and counts, never clinical content.

## Invariants that tests enforce

- Every `/api/*` request needs the header `X-Haven: 1`; GETs never write state (except audit rows). State-changing actions are POSTs.
- Original audio is kept only in `data/audio/` (0700, files 0600, server-made names, metadata in `audio_assets`) by `haven/audio.py`, and removed on sign-off (`HAVEN_AUDIO_DELETE_ON_CONFIRM`), at `HAVEN_AUDIO_TTL_HOURS` (default 72, a test setting) or by hand; a failed delete is `cleanup_failed` and retried by the sweep. Anything in `data/tmp` (upload or recording in progress) is removed on every failure path and by `files.clear_temp()` at start.
- Session ids are upper-cased (`_session_id`), and an upload's id must start with its client id.
- Errors are JSON with `error` (English) and `message_zh` (shown in the UI); `Refused` → 409, `BadRequest`/`BadNote` → 400, unknown → 500 with no detail.
- The web UI has no inline scripts/styles (strict CSP) and inserts all text as text (`el()` in app.js), never as HTML.
- Only simulated transcripts are tracked by git (`.gitignore` and `scripts/pre_commit_check.py`). `data/clients.json` is tracked and is modified by uploads and admin actions, so do not commit incidental changes to it.
